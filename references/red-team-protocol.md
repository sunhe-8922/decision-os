# Decision OS — 红队挑战协议

红队分析是 Decision OS 最关键的一层。本文件定义红队操作规范。

## 红队原则

1. **强制执行**：所有重大决策（Type 1）必须经过红队挑战，不可跳过
2. **人格独立**：红队分析者必须与决策者人格分离——假设自己是要证明这个决策错误的人
3. **结构化反驳**：不是泛泛质疑，而是针对具体假设和数据提出反证

## 红队三层攻击

### Layer 1：假设攻击

逐条检验决策所依赖的核心假设：

```
假设1：___
  支撑依据：___
  反驳证据：___
  假设失效条件：___
  假设失效概率：___ / 10

假设2：___
  ...
```

### Layer 2：数据攻击

检验数据质量和完整性：

```
数据点1：___
  来源：___
  时效性：___
  可能偏差：___
  缺失的更优数据：___

数据点2：___
  ...
```

### Layer 3：风险攻击

识别被低估或被忽略的风险：

```
已知风险1：___
  评估严重度：___
  实际可能严重度：___
  被低估的原因：___

被忽略的风险：___
  触发条件：___
  发生概率：___
  影响程度：___
```

## 红队输出格式

```markdown
## 红队挑战报告

### 最可能失败原因（Top 3）

3. ___

### 最脆弱假设

2. ___

### 红队结论
在现有信息下，此决策的致命缺陷是：___
建议补充信息/行动：___
```

## 红队触发阈值

| 决策类型 | 红队深度 | 最低时长 |
|---------|---------|---------|
| Type 1（不可逆）| 完整三层攻击 | 不设上限 |
| Type 2（可逆）| Layer 1 假设攻击 | 5 分钟 |
| 日常小决策 | 跳过红队 | 0 |
