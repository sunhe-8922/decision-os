# Decision OS — 情景推演与二阶效应

## 情景推演规范

### 三情景框架

每个重大决策必须构建三个情景。禁止只看单一结果路径。

```markdown
## 乐观情景（Bull）

概率：___%（三个情景概率之和 = 100%）
核心假设：___
关键指标变化：___
预期结果：___
触发信号：___

## 中性情景（Base）

概率：___%
核心假设：___
关键指标变化：___
预期结果：___
触发信号：___

## 悲观情景（Bear）

概率：___%
核心假设：___
关键指标变化：___
预期结果：___
触发信号：___
```

### 情景校准规则

1. **概率锚定**：先定 Base 情景概率（通常 40-60%），再分配 Bull 和 Bear
2. **禁止极端**：单一情景概率不得低于 10%，不得高于 70%
3. **对称性检验**：如果 Bull 和 Bear 概率之和 < 30%，说明 Base 情景定义太宽

### 期望值计算

```
期望收益 = Bull概率 × Bull收益 + Base概率 × Base收益 + Bear概率 × Bear收益
```

如果期望收益 < 0，该选项直接淘汰。

## 二阶效应分析

二阶效应并入情景推演，不作为独立步骤。在每个情景内部分析连锁反应。

### 分析框架

```
一级效应（直接结果）→ 二级效应（连锁反应）→ 三级效应（系统性影响）
```

### 示例：创业决策

| 效应层级 | Bull 情景 | Bear 情景 |
|---------|----------|----------|
| 一级 | 产品成功上线 | 产品延期 |
| 二级 | 用户增长→融资→扩张 | 现金流断裂→裁员 |
| 三级 | 行业地位→并购机会 | 个人信用受损→职业倒退 |

### 操作规则

1. **每个情景至少分析到二级效应**
2. **Type 1 决策必须分析到三级效应**
3. **如果二级效应中出现不可逆伤害，该情景概率必须上调**
